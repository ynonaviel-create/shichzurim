# מה כבר רץ במסד

מיגרציה היא קובץ הוראות למסד הנתונים, ומריצים אותה **ידנית**:
Supabase → הפרויקט `shichzurim` → **SQL Editor** → New query → הדבק את כל
הקובץ → **Run**. הצלחה נראית כמו „Success. No rows returned”.

## למה הקובץ הזה קיים

עד 08/08/2026 שום דבר בריפו לא הצהיר מה כבר רץ ומה לא. זה נשמע כמו קוסמטיקה,
אבל זה **מצב שנכשל בשקט**: הקוד באתר נפרס לפני שהמיגרציה רצה, המסד דוחה כל
כתיבה למרחב־שם שהוא לא מכיר, והתור זורק את הפעולה הדחויה בלי שהמשתמש רואה
שגיאה. זה בדיוק מה שקרה עם `0003` — ובגללו נדרשה `0004`.

## הכלל שמונע חזרה של הבאג

מרחב־שם חדש ב-`KEYMAP` שב-`assets/cloud.js` **חייב** מיגרציה תואמת שמרחיבה
את ה-`check` על `user_kv`, ושתרוץ **לפני** שהקוד עולה לאוויר. הסדר הזה לא
סימטרי: קוד ישן מול מסד חדש עובד; קוד חדש מול מסד ישן מאבד נתונים בשקט.

## כללים לפונקציות אנליטיקה

פונקציה חדשה → מיגרציה חדשה (לא לערוך ישנה) · `SECURITY DEFINER` + `is_admin()` ·
אגרגט בלבד · יום לפי `Asia/Jerusalem` · **רצפת מינימום של 10 עונים לכל נתון**
ברמת שאלה או מבחן — זו הבטחת הפרטיות לסטודנטים, ואין להוריד אותה בלי החלטה
מפורשת.
